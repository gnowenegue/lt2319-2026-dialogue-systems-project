# Project

## Introduction

The main part of the course is dedicated to a dialogue development/research project. Implement a functional (possibly incomplete) dialogue system application, and/or explore a specific dialogue feature. Default platform: **SpeechState**.

Individual work encouraged; pairs allowed. Groups of two must produce double the output, submit a more thorough report, and include a project diary detailing contributions (who, what, when).

### Suggested Themes (Preliminary)
* Interface to an existing API (optionally with SISU, LLM, or social robotics)
* LLM/RAG capabilities for dialogue (optionally with ISU or social robotics)
* SISU approach for dialogue (optionally with LLM/RAG or social robotics)
* Social robotics with Furhat (optionally with LLM/RAG or SISU)

**Requirements by Project Type:**
* **Explorative projects:** Explicit research question required.
* **Interface projects:** Behavioral specification including example dialogues required.
* **All projects:** Validation required (working demo, self-testing, user testing).

## Work Plan (Suggested for API Interface Track)

*Note: Research projects have a flexible structure but require clear research questions and standard sections: Intro, RQ, Method, Experiments, Results, Discussion.*

1. **Scenario & Protocol:** Define domain/API. Design human-human interaction scenario (one user, one system proxy) with task instructions.
2. **Data Collection:** Record 5–10 dialogues (audio requires transcription; text is acceptable).
3. **Analysis:** Distill recurring interaction patterns into target dialogue sets.
4. **Implementation:**
   * Build minimal viable prototype first.
   * Incrementally add dialogue capabilities matching observed patterns.
   * Debug and run user tests.
5. **Presentation Prep:** 15-minute presentation + demo.
6. **Report:** Document system; attach code and transcript appendices.

## Examination

* **Written report:** Standard report structure with code (pull request or zip file per supervisor instruction).
* **Presentation & demo:** 20 min total (10 min talk, 5 min demo, 5 min Q&A).

### Structure (Presentation & Report)
1. Introduction
2. Pre-existing service / API description (if applicable)
3. Data collection (scenario, collected data, distillation/analysis)
4. Implementation
5. Sample dialogues handled by system
6. Demo *(presentation only)*
7. Discussion (capabilities, edge cases, encountered issues)
8. Future work
9. Code *(report appendix)*
10. Raw & distilled dialogue transcripts *(report appendix)*
